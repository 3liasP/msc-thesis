\chapter{Conclusions}
\label{ch:conclusions}

This thesis designed, implemented, and evaluated an AI-powered documentation assistant for Sovelia Core that applies Retrieval-Augmented Generation in an on-premise PLM environment. The work demonstrates that RAG-based assistance can be integrated into enterprise systems under strict governance constraints while achieving usable response quality.

The evaluation indicates that documentation coverage and structure are the decisive determinants of answer quality in domain-specific RAG deployments. Retrieval and generation amplify both strengths and weaknesses of the underlying documentation: when the corpus is complete and consistently written, relatively simple retrieval strategies suffice, while missing or ambiguous source material limits performance regardless of retrieval complexity. This finding has direct implications for organizations considering RAG deployment, as it shifts focus from algorithmic sophistication to documentation quality as the primary lever for improvement.

The implemented architecture provides empirical support for a hybrid deployment pattern: retrieval and embeddings can remain on-premise while LLM inference is selected based on policy and performance needs. This pattern offers a pragmatic alternative to fully cloud-based or fully on-premise solutions, accommodating both data sovereignty requirements and practical performance constraints.

The evaluation approach contributes a factored assessment framework suitable for technical documentation assistants, especially for those deployed in PLM environments. Response quality was assessed across four separable dimensions (factual accuracy, relevance, source attribution, and completeness), enabling distinction between retrieval failures and generation issues. This diagnostic capability proved valuable for identifying specific weaknesses, such as missing procedural details or version context gaps.

Performance measurements illustrate that on-premise inference latency depends more on framework optimization and serving architecture than on raw GPU capacity. This observation separates the question of data residency from the question of inference efficiency, informing deployment decisions for organizations with strict on-premise requirements.

From a practical perspective, the work delivers a production-ready assistant achieving expert evaluation scores between 4,31 and 4,49 on a 5-point Likert scale across all quality dimensions. The architecture demonstrates that effective RAG can be implemented using existing PostgreSQL infrastructure augmented with pgvector, database-level access control, and a maintainable documentation pipeline. The design treats the assistant as an extension of existing PLM interfaces rather than a separate system, reducing integration complexity and preserving established permission models and overall architecture.

The research questions posed in Chapter~\ref{ch:introduction} are addressed through the design and evaluation. For RQ1 (architecture), the work demonstrates that PostgreSQL with pgvector provides adequate performance without requiring a separate vector database, while hybrid deployment supports both governance constraints and practical performance needs. Database-level access control enforcement aligns the assistant with existing PLM permissions and prevents information leakage. For RQ2 (pipeline engineering), the evaluation shows that reliability depends on predictable interfaces and lifecycle handling, while maintainability requires modular components, configuration-driven parameters, and version-aware updates. Chunking parameters should be treated as tunable configurations rather than fixed design decisions. For RQ3 (risk mitigation), the most critical risk proved to be insufficient documentation rather than technical failures. Access control risks are mitigated through retrieval-time enforcement, stale context through version-aware processing, and hallucination through required source attribution. Category-specific weaknesses in procedural and version-specific questions can be addressed through targeted documentation improvements and multi-step retrieval strategies.

The selected research methods proved suitable for answering the research questions. The systematic literature search established a baseline of concepts and implementation patterns for RAG, vector retrieval, and enterprise deployment under governance constraints. Design science research provided a coherent structure for producing prescriptive knowledge by building and evaluating an artifact rather than only describing a phenomenon. The single case study approach made it possible to validate the solution in the realistic constraints that directly determine success in practice, especially permission models, on-premise infrastructure, and documentation heterogeneity.

Although the artifact was implemented in Sovelia Core, several findings have broader processing potential and are significant also from a PLM research perspective. The results provide empirical evidence that documentation quality, permission-aware retrieval, and version-aware ingestion are decisive factors for AI-assisted documentation use in PLM, where workflows are governed, long-lived, and often version-dependent. These observations complement the largely conceptual nature of current enterprise RAG discussions by showing how common PLM documentation structures (release notes, help articles, SOPs) shape retrieval and answer quality in practice.

The dominant role of documentation quality, the need for permission-aware retrieval, and the value of version-aware ingestion are not PLM-specific, but apply to other on-premise enterprise systems where users rely on technical documentation (e.g., ERP, manufacturing execution systems, quality management systems, and other regulated environments). Similarly, the evaluated pipeline pattern (parse $\rightarrow$ chunk $\rightarrow$ embed $\rightarrow$ retire) and the factored evaluation dimensions support transferability because they describe how documentation assistants can be engineered and assessed independent of a single target system.

Several limitations constrain generalizability. The evaluation was conducted on a limited corpus and bounded question set. Production deployments may involve larger and more heterogeneous documentation, changing both retrieval behavior and answer quality. Performance results reflect specific hardware and deployment configurations. Expert evaluation provided detailed feedback, but limited evaluator numbers constrain statistical generalization. The question set focused on text-based queries, leaving multi-part questions and multi-modal needs underexplored. The study relied on expert rather than end-user evaluation due to the pre-release nature of the feature, limiting insights into real-world usability and impact.

Future work should focus on operational sustainability and user impact. Documentation improvement deserves dedicated attention through measurable quality indicators and evaluation of how targeted changes affect RAG answer quality. Integration questions remain challenging due to information distribution across system boundaries, motivating research on retrieval strategies that connect CAD, PLM, and ERP concepts. On-premise inference performance can likely be improved through modern multi-GPU serving frameworks. User-facing evaluation should complement expert judgement through longitudinal studies measuring task completion, time-to-resolution, and adoption patterns.

This work demonstrates that RAG can provide practical value in on-premise PLM environments when implemented as a governed extension of existing systems. The evaluation supports the insight that documentation quality is typically the main limiting factor. For organizations considering similar deployments, technical implementation and documentation improvement should be treated as a combined effort: the system makes existing knowledge easier to access while revealing where that knowledge is missing. An on-premise, PostgreSQL-based RAG architecture with permission-aware retrieval and maintainable ingestion can satisfy governance requirements while providing usable response quality, establishing a baseline for further development of documentation assistance in enterprise contexts and in Sovelia Core specifically.
